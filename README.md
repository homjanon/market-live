> **国内直连**：https://homjanon.github.io/market-live/（GitHub Pages，中国内地直连）

## 数据板块

### ⛓ 指数 / 汇率：四层兜底路由（2026-09-22 起）

19 只指数 + 汇率统一走一条「主源 + 三层兜底」链路，每项结果带 `source` 字段标明实际命中来源：

| 层级 | 数据源 | 覆盖 | 请求／次 |
|---|---|---|---|
| ① 主 | 东财 `ulist.np` **批量** | 全部 20 项 | 1 |
| ② 备 | 腾讯 `qt.gtimg.cn` | A股 6 + 北证50 + 国债ETF 2 + 港股 3 | 1 |
| ③ 备 | 新浪 `hq.sinajs.cn` | A股 6 + 北证50 + 港股 3 + 全球 5 + A50期指 + 汇率 | 1 |
| ④ 兜 | Yahoo `v8 chart` | 除北证50外全覆盖（含斯托克600、红利低波ETF） | 按缺口，每项 1 |

- **正常路径只有 1 次请求**（东财批量一次拿全 20 项）。原实现是 **21 次并发单条请求**，实测会触发东财对 Cloudflare 出口的定向风控——连续请求后整批 `RemoteDisconnected`，线上表现为「A股 / 港股 / 全球指数大面积缺失，而走 Yahoo 的美股毫发无伤」。
- 东财失败时才启用后三层（并发，1 轮往返），逐项按 腾讯 → 新浪 → Yahoo 取第一个有效值；**缺口在各层填充之后重算**，避免把已覆盖的品种重复打一遍 Yahoo。
- 下表「主源」列即东财 secid；兜底源按上表路由。

**三个已知边界（均为 2026-09-22 逐品种实测结论）：**

- ⚠️ **腾讯不能兜全球指数**：`usDAX` 实为「DAX德国指数ETF」（≈45）、`usCAC` 实为「卡姆登国家银行」（≈57），撞名会**静默写入完全错误的值**，比缺失更危险 → 全球 6 项一律不走腾讯。
- ⚠️ **新浪不能兜斯托克600**：`znb_SXXP` 返回陈旧错值 554.52（实际 ≈643）→ 该项跳过新浪，直落 Yahoo。
- ⚠️ **北证50 无 Yahoo 代码**（`899050.BJ` 返回 404）→ 止于腾讯 / 新浪。

> **2026-09-22：原「红利低波无兜底」这一边界已消除。** 该品种由中证红利低波指数（`2.H30269`，全网仅东财有）
> 换成 **红利低波ETF（512890）**，四层全覆盖（东财 `1.512890` / 腾讯 `sh512890` / 新浪 `s_sh512890` / Yahoo `512890.SS`），
> 实测四源同值（1.187 / +0.08% / 昨收 1.186）。**至此 20 项全部具备兜底，已无单源品种。**
>
> 换用 ETF 后 **最新价由指数点位（10897.72）变为基金价格（1.187 元）**，与同表 `30年国债ETF 109.38`、`十年国债ETF 134.821` 的报价口径一致。
> 显示名改为「**红利低波ETF**」，但内部字典 key 与前端分组清单**仍沿用「红利低波」**——前端用 `names.filter(n=>idx[n])` 过滤，
> 改 key 会让该行**不报错、直接不渲染**；而显示列取的是 `o.name`，因此只改显示名即可**零改动前端**。

**两处取值自校验：**

- 东财批量用 `f2`(价) / `f18`(昨收) / `f3`(涨跌幅)。涨跌幅以**同一响应内**的 `f2/f18` 自算——两个价格同处一条响应，比值对 `fltt` 量级开关不敏感；与源报 `f3` 相差 >0.3pp 即判定 `fltt=2` 未被采纳（整条放大 100 倍），**整行作废**并让位兜底源。
- 对东财同域请求加**并发闸（≤6）**，降低触发风控概率。

## 计算指标

### 小旭恐惧指数（XXFI）

**XXFI = 恐惧 4 项加权总分**（代码 `xxfi = fear`）；另有一套**贪婪分项**合成 `GreedIndex`（旁路展示，**不参与 XXFI 判定**）。
与 [xiaoxu-fear](https://github.com/homjanon/xiaoxu-fear) 同源计算。

**恐惧分量（值越高→越恐惧→反向看多）：**

| 分量 | 权重 | 公式 | 数据来源 |
|---|---|---|---|
| 回撤 drawdown | 0.30 | clamp(abs(dd)×500) | 上证指数 20 日 K + 当日 spot（新浪） |
| 广度 breadth | 0.25 | clamp((down/up-0.5)×100) | 乐咕乐股 legu（全市场涨跌家数） |
| 跌停比 limitdown | 0.20 | clamp((ld/lu)×50) | 乐咕乐股 legu（涨停/跌停家数） |
| 波动率 vol | 0.25 | clamp(vol_pct×100) | 上证指数 20 日波动率分位（新浪） |

**贪婪分量（值越高→越贪婪→反向看空）：**

| 分量 | 权重 | 公式 | 数据来源 |
|---|---|---|---|
| 动量 momentum | 0.4167 | clamp(ret20×500) | 上证指数 20 日涨幅（新浪） |
| 涨停比 limitup | 0.25 | clamp((lu/ld)×50) | 乐咕乐股 legu |
| 超买 overbought | 0.3333 | clamp(above×500) | 上证指数高于 20 日均线幅度 |

> **2026-09-22：资金流整体下线。** 原「散户追高 retailin（0.20）」与「背离 divergence（0.20）」两项依赖东财沪深两市资金流，
> 现连同 `fetch_fund_flow()` 一并移除；余下 3 项按原比例 **5 : 3 : 4 归一化**（原合计 0.60 → 1.0），保持 `GreedIndex` 量纲不变。
>
> 下线依据（三条，均经代码与上游仓核对）：
> ① **XXFI 主指标只取恐惧 4 分项**，资金流仅进旁路 `greed` —— 连 xiaoxu-fear 原版的 `interpret(xxfi, greed)`
> 都**从未在函数体内使用 `greed`**，属移植残留，不是「被裁掉的功能」；
> ② market-live 未保留原版「贪婪副表」（前端虽写了 `const g = c.greed`，模板里一次未用）；
> ③ 贪婪指数原有 **40% 权重长期压在写死的占位值上**（retailin=0、divergence=50），本就不构成有效信号。
>
> 附带收益：少一路东财请求（东财正是被定向风控那家），`degraded` 不再常驻「主力/散户资金流」。
> 为前端兼容，`divergence` / `divergence_state` 字段仍保留（恒为 `null` / 固定文案「资金流未接入（不参与本指标）」），不会显示 undefined。
>
> **市场级资金流没有可用的非东财替代源**（2026-09-22 实测）：新浪 `MoneyFlow` 大盘/板块接口返空数组、腾讯两端点 404、同花顺 401；
> 唯一 1 请求出市场级的是东财 `fflow/kline`，但**同属东财**，换端点不改变故障模式。
> 个股级源（`data_fund_flow` / `fflow` / `PRIME_INFLOW` / `r0_net+r1_net`）与「沪深两市整体」粒度不匹配，Worker 内需聚合全市场约 5400 只，不可行。

**XXFI 信号阈值**：

| XXFI | 信号 | 含义 |
|---|---|---|
| ≥75 | **BUY** | 极度恐惧，分批低吸 |
| 60–74 | **ACCUMULATE** | 恐惧，逢低吸纳 |
| 40–59 | **HOLD** | 中性，按策略持有 |
| 25–39 | **REDUCE** | 偏贪婪，逢高减仓 |
| <25 | **SELL** | 极度贪婪，减仓避险 |

> **D2 口径说明（2026-09-14 补充）**
>

> 页面上会同时给出「跌超2.5% 的只数/实到只数」与「全篮子下跌只数」两个数，便于对照。
>
> 同日加固：出现以下任一情况时，ETF 占比一律置空、页面上显示**具体原因**（如"空返回""实到 42/45""涨跌幅缺失 6/45"），
> 不再把取数失败静默显示成 0%：
> ① 有效涨跌幅缺失 ≥ 10%；② 实到只数 < 45 × 90%；③ 任一 |涨跌幅| > 30%（`fltt=2` 失效时东财会返回放大 100 倍的值）。
>
> **2026-09-22 补充**：① ETF 篮子加**腾讯兜底**（`qt.gtimg.cn` 一次请求 45 只，实测 45/45 命中），上述三道校验在兜底路径上同样生效；

### 年内涨跌幅（YTD）

各表格「年内」列的计算方式：

```
年内涨跌幅 = (当前价 ÷ 当年首个交易日收盘价 − 1) × 100%
```

- 年初基数**一年不变**，年内只随当前价实时变化，不重复抓取；

#### 缓存与兜底机制

```
每次运行 load_ytd_bases():
  1) 读 KV ytd_base_v2_{年份}（如 ytd_base_v2_2026）
  2) 仅对 KV 缺失的品种增量抓取（新浪A股 / 东财 / 新浪美股）
  3) 仍缺失且静态表 YTD_BASE_STATIC 有值 → 用静态值兜底（不覆盖动态抓取值）
  4) 整表写回 KV
```

- **年内不变**：基数当年首个交易日抓取一次后写入 KV，后续运行直接读 KV，不再重复请求外部接口（也避免了新浪美股 300–600KB 大响应的重复开销）；
- **跨年自动重置**：年份换 key（`ytd_base_v2_2027`），2027 年首个交易日自动全量重抓，无需手动干预；
- **静态表兜底**：东财海外 secid 偶发 520/断连时，港股/全球/美股年内仍可正常显示；
- **换标的必须配套升 key（2026-09-22 踩过，务必记住）**：读取逻辑是「KV 里已有的键永不重取」，而红利低波由
  指数换成 ETF 后，旧 key 里仍缓存着**指数点位 11235.18**——若不升 key，会把 ETF 价格除以指数点位，
  YTD 直接算成 **-99.99%**。故本次把前缀升为 `ytd_base_v2_`，强制全量重抓一次。**今后任何换标的/换口径的改动都要配套升 key。**

## 运维诊断（API）

| 端点 | 作用 |
|---|---|
| `/api/data` | 返回当前快照（直接读取 KV，无需重新抓取） |
| `/api/refresh` | 手动刷新：同步构建并写入 KV、推送 GitHub Pages（等价于 Cron 跑的逻辑） |
| `/api/cron_diag` | 定时触发诊断：返回最近一次 Cron 的状态（`enter` / `dispatched` / `error`），含 `is_tx`、`err`、`tb` 字段（GitHub 推送状态见 `gh_push_public`），用于排查“自动触发没跑”问题。另含 **`src_diag`**：数据源路由诊断（`by_source` 各层命中数、`missing` 缺口、`layers` 每层命中/失败原因、`etf_source`），用于回答“这次刷新每个品种的数据来自哪一层、哪层为什么失败” |

**Cron 健壮性**：`scheduled(self, controller, env, ctx)` 按 Cloudflare 运行时签名接收 4 个位置参数；绑定一律通过 `self.env` 获取——位置参数里的 `env` 在 Python Workers 的 scheduled 上下文并非真实绑定对象，曾导致 KV / GitHub 写操作静默失败。全程 `try/except` 把状态写入 KV：`_cron_diag`（定时触发 `enter`/`skipped`/`dispatched`/`error`）与 `_gh_diag`（GitHub 推送 `no_token`/`error`/`ok`），**不再静默失败**。
> **2026-07-24 修复记录**：① `scheduled` 改由 `self.env` 取绑定（原位置参数 `env` 静默失效）；② 补全 `GITHUB_TOKEN` secret，GitHub Pages 自动推送恢复；③ 新增 `_cron_diag` / `_gh_diag` 诊断留痕。

## 与 xiaoxu-fear 的关系

本项目的 XXFI 计算与 [xiaoxu-fear](https://github.com/homjanon/xiaoxu-fear) 同源：**恐惧 4 分项的公式、权重、阈值与文本逐行一致**（XXFI = 恐惧总分）。

- **贪婪分量**：原版为 5 项，本项目 2026-09-22 起为 3 项（下线资金流相关的 retailin / divergence）。
  但原版 `interpret(xxfi, greed)` 从未在函数体内使用 `greed`，故**对 XXFI 信号没有任何影响**（见上方「贪婪分量」说明）；
- xiaoxu-fear 使用 akshare 取数（本地/GitHub Actions）
- market-live 使用直连 HTTP API 取数（Cloudflare Worker 无 akshare）
- xiaoxu-fear 输出为 GitHub Pages 静态报告
- market-live 为实时滚动看板（每 30 分钟刷新）
